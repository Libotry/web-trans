# 文字版 PDF 双语翻译：设计方案 v1

日期：2026-10-31。状态：v1.1.0 的设计基线，主体功能已实现；实际验证范围见 [验证记录](../VERIFICATION.md)。

本文保留设计阶段的功能边界、目标与验收清单；未勾选项不代表均已完成实际样本验证，具体可用行为以 [README](../README.md) 为准。

实施补充：PDF.js 固定为 6.4.299，采用含兼容垫片的本地 legacy 模块；显式创建本地 Worker 并传入 PDFWorker，避免扩展不透明来源导致库创建 blob 包装。禁用 Wasm，无需放宽现有 CSP。PDF_PAUSE 用于暂停与页切换；停止会关闭自动翻页翻译。每阅读页最多保留最近 10 个文档计数账本，已淘汰/重新导入的文档视为新任务。首版只保留当前页画布和受总文字预算约束的提取结果，不额外预渲染相邻页面。

## 1. 目标与关键决策

让用户在扩展内打开文字版英文 PDF，保留原始页面，在旁边阅读按页、按段对应的简体中文翻译；继续使用现有的自定义 Chat Completions API、模型与密钥配置。

**首版选择：本地导入 + 独立扩展阅读页 + PDF.js 本地解析 + 左右对照 + 当前页主动翻译。**

不尝试向 Chrome 内置 PDF 阅读器注入脚本，也不替换浏览器默认 PDF 打开方式。用户已经在 Chrome 打开的 PDF，先保存到本地，再通过扩展导入。此路径对本地和在线下载的文档统一可用，不依赖内置阅读器的内部页面结构。

### 功能边界

| 项目 | 首版范围 |
| --- | --- |
| 文档导入 | 文件选择器、拖放单个本地 PDF；切换文件需确认结束当前任务 |
| 文档类型 | 有可提取文字的英文 PDF；优先横排、单栏，常规双栏尽力识别 |
| 翻译方向 | 英文 → 简体中文，与网页翻译一致 |
| 阅读方式 | 左侧原始 PDF，右侧同页的原文段落及中文；窄屏上下排列 |
| 翻译触发 | 点击“翻译当前页”；可开启“翻页后自动翻译”，默认关闭 |
| 任务控制 | 暂停/继续、停止、失败项手动重试、增加额度、清除本文件译文 |
| API 与费用 | 复用现有配置；与网页共享最多两个并发请求；按文档限制请求次数 |
| 保存策略 | 文件字节、提取文字、阅读状态和完整译文只驻留阅读页内存；后台仅保留有界会话翻译缓存及任务元数据 |
| 不做 | OCR、远程链接直接抓取、整本自动翻译、译文 PDF 导出、原位排版替换、精确表格还原、跨设备同步 |

不承诺所有“可复制文字”的 PDF 都能正确排序；缺少字符映射的文件也可能提取乱码。扫描页、图表、公式和异常编码必须明确提示，不将无意义文本发送给 API。

## 2. 用户流程与界面

### 2.1 打开文件

1. 扩展弹窗新增“PDF 翻译”按钮，打开扩展自身的阅读标签页。
2. 页面说明：“PDF 在本地解析。点击翻译后，仅将待翻译文字发送给你配置的模型服务。”
3. 通过选择或拖放打开文件，先检查大小和 PDF 头，再解析；扩展名及 MIME 仅作辅助判断。
4. 展示总页数、当前页原始图像与提取预览；**打开文件本身不调用模型**。
5. 尚未配置 API 时允许阅读和提取预览，点击翻译时提供设置入口。

页面刷新、关闭、扩展重载或浏览器重启后需重新选择文件。首次打开时明确说明这一点，不以“已缓存”暗示能够恢复整个文件。

### 2.2 阅读与翻译

```text
PDF 双语阅读                         设置 API | 打开其他文件
paper.pdf           第 [3] / 24 页    [上一页] [下一页] [缩放]

[翻译当前页] [暂停] [停止] [重试失败项]
□ 翻页后自动翻译（仅当前页，不预取下一页）
本文件已请求 12 / 100 次 · 已完成 32 段 · 失败 1 段 · 缓存命中 4 段

┌──────────────────────────┬──────────────────────────┐
│ 原始 PDF 第 3 页          │ 第 3 页段落对照            │
│                          │ ① 英文原文                │
│ 原始版式、图表、文字       │   简体中文译文             │
│                          │ ② 英文原文                │
│                          │   等待 / 翻译中 / 失败重试   │
└──────────────────────────┴──────────────────────────┘
```

- 两侧始终对应同一页；首版不做像素级滚动联动。点击右侧原文段落，在左侧临时高亮对应文字区域；不能可靠定位时只展示页码，不伪造精确定位。
- PDF 侧保持原始布局，右侧以纯文本卡片展示，不把中文覆盖到 PDF 上。
- 页内拆分后的长段落按切片顺序合并展示；部分切片失败时保留成功项，明确标记缺失位置。
- 翻页后停止为旧页派发新请求；旧页已发出请求可以完成，结果只更新旧页记录，不能写到新页。
- 新页默认只解析和预览；开启自动翻译后，约 300ms 稳定停留才调度，快速翻页不能触发整串请求。
- 已完成译文在本阅读页内保留，返回该页直接显示。再次点击翻译只补未完成项，不重复提交成功项。
- 有失败项的页面显示“部分完成”，不宣称整页翻译成功。进度分别展示当前页与全文件已处理量，不把未解析页面算作已识别段落。

### 2.3 控制语义

- **暂停**：停止新增请求，已发出的可以完成；继续时只调度当前页。
- **停止**：取消当前文档任务代数，尽力中止在途请求，保留已完成结果；迟到结果不再写入。再次开始会创建新代数，沿用本文件已消耗额度。
- **重试失败项**：用户主动触发，只处理当前页失败切片，也计入额度；超时可能已经计费，不自动重发。
- **清除本文件译文**：确认后停止任务、清除页面结果，回到可阅读状态；不重置已消耗额度、不暗中发起请求，也不承诺清除后台共享缓存。清除会话缓存仍使用设置页入口。
- **增加额度**：显式增加一份配置中的请求额度，累计用量不归零。
- **关闭/换文件**：尽力中止任务并释放渲染资源。关闭通知只作优化，后台还必须通过标签页关闭事件和身份校验清理。

## 3. 与现有实现的衔接

当前源码采用原生 JavaScript ES modules，无运行时框架：

- `extension/core.js` 已包含英文判断、长文切分、请求构造和按 ID 解析结果，可直接复用或小范围抽取。
- `extension/background.js` 已负责 API Key、权限、API 调用、会话缓存、全局并发和网页任务校验。
- 现有 `jobFor()` 依赖网页发送者的 tab、frame、document 与 token，不能直接放宽后交给 PDF 页共用。
- 现有网页任务按标签页保存，计数与控制语义也与页面绑定；PDF 需要独立的任务类型和额度累计方式。

**改造原则：共享 API 执行能力，不共享宽松的消息授权。**

先把批次校验、缓存读写、获取全局并发槽、API 调用与结果校验整理为公共执行路径，网页和 PDF 各自通过专属身份校验后才能进入。保留现有网页消息协议和表现，添加回归测试，不借机重写网页功能。

## 4. 技术架构与依赖

```text
弹窗 → 扩展 pdf.html 阅读标签页
             ├─ File / ArrayBuffer（只在本地）
             ├─ PDF.js Worker：解析、提取文字
             ├─ Canvas：当前页原始渲染
             ├─ 版面归组 / 英文过滤 / 切片 / 页面状态
             └─ PDF 专用消息：任务身份 + 小批文本
                            ↓
                  扩展 Service Worker
                  来源校验 → 配额 → 共享并发/缓存 → 模型 API
                            ↓
                  按任务、页、切片 ID 回填
```

### 4.1 PDF.js 集成

- 选用实施时确认兼容目标 Chrome 的 PDF.js 稳定版，固定精确版本与完整性校验；记录来源、许可证和升级办法。
- 库、Worker、必要的字符映射和标准字体资源全部随扩展打包，不从 CDN 加载、不执行远程脚本。
- 采用适合本扩展的本地模块与 Worker 路径；实现阶段验证其 Worker、字体和可能的 Wasm 行为与 MV3 CSP 的兼容性。优先选择无需放宽当前脚本策略的加载配置；若确实需要额外 CSP 能力，必须先记录原因并单独评审，不能添加远程脚本或宽泛 `unsafe-eval`。
- 不启用 PDF 文档脚本执行、不渲染表单交互、不执行嵌入动作、不打开附件。首版 PDF 侧仅渲染画布与受控高亮，避免引入可点击外链层。
- 使用 `getDocument({ data })` 本地解析，固定本地资源路径；不采用库自带的完整通用 Viewer，减少额外功能与攻击面。
- 选中的文件字节可被 Worker 转移所有权；不能假设原 ArrayBuffer 转移后仍可用。文档身份使用随机 UUID，无需为首版跨会话恢复计算整本文件哈希。

### 4.2 权限

文件选择器和拖放足以读取用户明确选择的文件，**不新增 file:// 全盘访问权限**，不要求打开“允许访问文件网址”。新阅读页不向网站暴露为 web-accessible resource，也不设置外部消息入口。

API 仍只向设置中保存的 HTTPS Endpoint 请求，使用现有可选主机权限流程；不增加 cookies、history、webRequest、下载目录扫描等权限。若实施发现其他权限需求，先说明用途再决定。

## 5. 文字提取与段落重建

### 5.1 处理管线

当前页 `getTextContent()` → 过滤无效项 → 坐标归一化 → 字符/词合行 → 版面分区 → 行合段 → 英文筛选 → 长段切片 → 预览 → 翻译。

所有文字位置统一到不受当前缩放影响的页面坐标，保留页旋转和视口变换关系；高亮时再映射到当前画布坐标。切换缩放不得重新生成段落 ID 或调用 API。

### 5.2 首版版面规则

1. 忽略空字符串；保存文字项的位置、宽高、方向、字体及原始次序，不能直接 `items.map(...).join(' ')`。
2. 按接近基线归行，容差相对于该行字高设置；词间是否补空格结合几何间距，避免把所有字符粘在一起或逐字插入空格。
3. 根据行框和明显留白识别单栏/双栏区域。先处理跨栏标题，再按左栏到右栏、栏内从上到下排序；无法可靠分栏时提示“阅读顺序可能不准确”，允许用户查看提取预览后决定是否翻译。
4. 综合行距、缩进、字号变化和列表标记分段，保留标题和列表。仅合并同页、同栏的连续正文，不跨页合并段落。
5. 不盲目删除连字符：只在行尾连字符、下一行小写词等条件下保守合并；保留原始提取文本供排查，常规复合词不能被任意改写。
6. 公式、纯数字、URL、明显代码和以中文为主的文本不发送。复用现有英文筛选，但为 PDF 短标题和乱码检测补充测试。
7. 表格首版按可识别文字块尽力处理，不承诺保留行列关系。页眉、页脚和脚注先保留；首版不为识别重复页眉而扫描整本，也不做可能误删正文的自动去重。
8. 非横排/混合旋转布局、重叠文字、复杂多栏显示兼容性警告；标准整页旋转通过视口变换处理。

提取质量判断综合有效字母数、替换字符比例和文本覆盖情况。没有文字显示“本页未提取到可翻译文字，可能为扫描页”；少量文字显示“仅提取到少量文字，图片区域未识别”。不据单页结果宣称整本都是扫描件。

### 5.3 段落与切片身份

```text
Document: documentId(UUID), generation, pageCount, configFingerprint
Page: pageNumber, extractionVersion, status, blocks[]
Block: blockId, order, sourceText, boundingRects[], warnings[], chunks[]
Chunk: chunkId, sourceText, state, translation?, error?
```

`chunkId` 使用受控短标识，包含页、块和切片序号；后台另行校验文档任务。界面内部把 ID 映射回原文，不依赖模型输出顺序。段落顺序在同一次提取内稳定；算法升级时递增 `extractionVersion`。

每个切片不超过 1800 字符；沿用现有后台硬限制：每批最多 6 段、单段最多 2000 字符、合计最多 6500 字符、ID 最多 100 字符且互不重复。优先在同页组批，不跨页混合。

## 6. 任务协议与安全边界

新增 PDF 专用消息，字段示意如下；字段长度、枚举和来源均需在后台校验：

| 消息 | 输入 | 后台行为 |
| --- | --- | --- |
| `PDF_START` | `documentId` | 校验阅读页来源，创建新任务，返回 `taskId/token/generation/configFingerprint` |
| `PDF_TRANSLATE` | 任务身份、`pageNumber`、`segments` | 校验拥有者和批次，进入公共翻译执行器 |
| `PDF_CANCEL` | 任务身份 | 标记代数失效，中止该任务在途请求 |
| `PDF_EXTEND` | 任务身份 | 增加本任务可用总额度，不把累计请求数清零 |
| `PDF_STATUS` | 任务身份 | 返回计数、额度、配置失效/任务失效状态，不返回密钥 |

- 后台只接受同一扩展 ID、**精确为本扩展 `pdf.html` 路径**、主 frame 的请求，并绑定首次注册的实际 tab ID 与 document ID；缺少所需身份时拒绝注册，而不是回退到宽泛受信任页面。
- `documentId` 是前端文档标识，不是访问授权；后台生成的随机 token、拥有者 tab/document 及代数必须全部匹配。普通网页、其他阅读标签页及旧页面不能复用任务。
- 精确路径校验使用 URL 解析后的 origin/path，不用宽泛字符串前缀判断。PDF 消息不接受任意 Endpoint、请求头、API Key 或模型参数。
- API Key 只由后台读取并用于请求；PDF 阅读器通过配置接口取得非敏感设置和 hasKey，不直接读取凭据存储。扩展阅读页仍属于受信任上下文，此约定不是对恶意扩展代码的隔离承诺。
- 返回结果必须同时匹配任务代数、配置指纹、页面和切片；模型返回 HTML/Markdown 一律用纯文本展示。
- 文件名、提取文本、密码和译文不写日志；错误提示不拼接完整服务响应、认证头或文件正文。

### 配置变更

任务开始时固定 endpoint/model/jsonMode/promptVersion 等翻译相关配置及凭据版本标识；Key 本身不传给阅读页。每次派发前后台验证配置仍匹配。相关配置或密钥变化后暂停任务，提示“配置已变化，请重新开始”；已发出的结果不混入新配置下的结果。字号等纯展示设置不触发重翻。

### 密码与异常文件

支持 PDF.js 的密码回调，在阅读页临时输入密码；密码不发送后台、不持久化，关闭文件后清空引用。密码错误可重试或取消；损坏文件、无法解密或不支持的加密明确报错，不尝试绕过访问控制。对有复制限制的文档先提示限制，首版不提供绕过功能。

## 7. 调度、缓存与恢复

### 调度与计费

- 当前页驱动队列，网页与 PDF 共享两个并发槽；相同文档最多保留两个待执行批次，翻页、暂停、取消后不在后台堆积整本内容。
- 获取并发槽后重新校验任务、配置、暂停/页状态与额度，再扣减计数、发起请求。尚未派发的旧页队列项丢弃；释放并发槽必须在 finally 完成。
- 初始文档额度取设置的 `limit`（默认 100），本文件各页、手动重试共享。缓存命中不扣请求额度，已经派发的失败/取消请求不返还额度。
- 401/402/403 停止该任务，修正配置后显式重新开始；429、5xx、断网、超时、格式错误均不自动重试。
- 只显示服务返回的已知 token，用量缺失显示未知；不估算价格或承诺取消后不收费。

### 缓存

复用后台批次缓存，键包含 endpoint、model、jsonMode、凭据摘要、实际文本与 promptVersion；若加入 PDF 专用提示词，必须使用独立版本。只缓存全部切片校验通过的批次，部分成功留在阅读页内存。

沿用会话级存储，但把现有“只按条数清理”改为条数与估算字节双上限，建议起点为 150 批 / 4 MiB，受实际 storage.session 可用空间约束；写缓存失败应降级为不缓存，不把成功翻译当作失败。文档原始字节和全文不放入该缓存。

清除设置页会话缓存覆盖网页与 PDF；不自动删除阅读页已经展示的译文，界面说明“缓存已清除，已打开页面的结果仍保留”。

### Service Worker 中断

任务拥有者、代数、累计计数、上限及配置版本写入 storage.session；不保存 PDF 全文。阅读页保留页面结果和队列。后台重启后通过任务身份和状态对账；未派发项可继续，派发但没有响应的批次标为“结果未知”，需手动重试，不自动重复计费。

计数保存与网络发送无法形成跨进程事务：崩溃窗口可能保守占用一次额度但未真正发出，应明确不保证计数等于服务账单。关闭标签页清理任务；后台启动时清理已不存在或身份失效的拥有者。任何恢复都不能把旧任务绑定到新阅读页。

## 8. 性能与资源限制

以下是首版建议值，实施与样本文档验证后再调整，不作为尚未测试的性能承诺：

| 项目 | 建议限制/策略 |
| --- | --- |
| 文件大小 | 最大 50 MiB，读取前检查 |
| 页数 | 最大 500 页，取得元数据后检查 |
| 单页提取 | 最多 50,000 个文字项、200,000 个字符；超过时停止该页翻译并提示 |
| 画布 | 单画布不超过约 12 百万像素，高 DPI/高缩放下限制输出倍率 |
| 渲染 | 只保留当前页及至多相邻两页画布；离开页面取消过期 RenderTask |
| 提取缓存 | 最近 10 页解析中间态；已翻译页保留必要原文和结果 |
| 文本内存预算 | 原文与译文累计约 20 MiB 时停止新增提取，提示重新打开文件或结束任务；估算不等于实际 JS 堆大小 |

文件大小不是内存消耗上限，压缩 PDF 仍可能异常膨胀。处理时分阶段让出主线程，用户取消时销毁 loading/document task，取消渲染，清空画布、文件引用和对象 URL；不声称以上限制能完全防御所有恶意 PDF。依赖安全更新与异常样本测试是必要条件。

## 9. 拟议文件与开发顺序

保持原生 ES modules。以下路径均为待新增或待修改的实现位置：

```text
extension/
  pdf.html / pdf.js / pdf.css    阅读页与任务控制
  pdf-extract.js                纯数据版面、合行分段、质量检测
  pdf-state.js                  页状态、切片、版本与过期结果判定
  vendor/pdfjs/                 固定版本库、Worker、字体与字符资源、许可证
  background.js                 PDF 消息授权、任务元数据、共享执行入口
  core.js                       复用/抽取批次和配置指纹相关工具
  popup.html / popup.js         PDF 阅读器入口
  manifest.json                 必要时仅调整本地依赖加载相关配置
scripts/
  vendor-pdfjs.mjs               可复现依赖复制与版本校验
tests/
  pdf-extract.test.mjs           版面规则单元测试
  pdf-background.test.mjs        身份、额度、取消、配置与恢复测试
  pdf-browser.test.mjs           真实 PDF.js 与阅读页集成测试
  fixtures/pdf/                 可合法再分发的最小测试 PDF
```

开发阶段可引入锁定版本的开发依赖和 lockfile，将所需静态资源复制进扩展；用户加载已准备好的 extension 目录仍无需安装 Node.js。生成资源必须有可复现来源，不手工修改第三方库。fixture 中不放真实用户文件、密钥或受版权限制的论文。

按四步交付：

1. **本地阅读闭环**：入口、文件/密码处理、本地 Worker、原始页面渲染、文字预览；无 API 调用。
2. **提取与段落对照**：单栏/双栏规则、稳定 ID、高亮、乱码/扫描页提示和资源限制。
3. **翻译闭环**：后台任务授权、共享执行器、额度、缓存、暂停/取消/重试、配置变更与后台恢复。
4. **验收与说明**：自动化测试、真实扩展加载验证、少量用户确认后的真实 API 冒烟测试、更新 README 与验证记录。

### 可验证验收项

- [ ] 文件导入与预览完全本地完成，未点击翻译且未开启自动翻译时没有模型请求。
- [ ] 代表性单栏/常规双栏样本按人工标注的阅读顺序提取；无法可靠处理的样本明确告警，不承诺完美恢复排版。
- [ ] 当前页原文与译文按稳定 ID 配对，缩放/翻页不重复请求，旧页结果不写到新页。
- [ ] 扫描页、乱码页不会批量发送无意义内容；文字/扫描混合文件按页给出正确提示。
- [ ] 网页与多个 PDF 阅读页同时翻译时，总 API 并发不超过 2；缓存命中不扣额度，重试计入额度。
- [ ] 暂停后不新增请求；停止/换文件/关闭后不新增该任务请求；取消和超时明确提示可能计费。
- [ ] 后台中断后结果未知项不自动重发；配置变化不混用新旧译文；额度不因停止/重新开始静默归零。
- [ ] API Key 不出现在 PDF 消息、DOM、日志；文件字节、密码、文件名不发送给模型服务；待翻译文本的发送可由模拟端核验。
- [ ] 模型文本、文件名、PDF 提取内容中的 HTML/脚本均不会执行；PDF 文档脚本/嵌入动作不执行。
- [ ] 所有解析依赖从扩展本地加载，无 CDN 请求；不新增全盘文件访问或不必要权限。
- [ ] 达到资源上限可以可控退出，重复开关文档无持续资源累积；不以单一样本宣称覆盖所有 PDF。
- [ ] 现有网页翻译测试及实际扩展加载验证仍通过，验证记录区分模拟 API 与真实 API。

## 11. 风险与后续扩展

最大风险是 **PDF 文字阅读顺序与段落重建**，不是 API 调用。先用固定样本验证提取质量，再扩大支持范围；原始 PDF 与英文提取预览始终可读，不能用流畅的译文掩盖错误排序。

后续可独立增加：用户选择页范围翻译、手动调整阅读顺序、远程 URL 导入、持久文档库、OCR、术语表、可导出双语文档。远程 URL 导入涉及权限、重定向、认证和大小限制，OCR 涉及额外算力与隐私，均不混入本首版。

**本方案待确认的默认决策：先支持本地文件，不直接接管 Chrome 内置 PDF 阅读器；只按当前页翻译；不做 OCR 与导出。**
