# PDF 当前页接管与页内译文：设计方案 v2

日期：2026-10-31。状态：v1.2.0 实施基线，主体功能已实现，实际验证范围见 [验证记录](../VERIFICATION.md)。

本方案增量扩展 [PDF v1 设计](design-pdf-v1.md)，保留本地导入、文字提取、API 配置和任务调度。下文保留设计阶段的目标与验收清单；未勾选项目不代表均完成真实样本验证，可用行为以 [README](../README.md) 为准。

实施补充：来源候选使用 `pendingUrl || url`，在已提交的 Chrome 原生 PDF 标签页实际验证无需新增 tabs 权限；读取不到时允许精确扩展弹窗中的显式粘贴兜底。页内/左右 PDF 对照/原文/列表共享同一任务和覆盖层调整记录。默认白色逐行遮罩，不声称理解图像背景；风险版面降级列表，溢出通过完整原文/译文对话框阅读。网络下载和来源交接纯内存；后台重启丢失来源记录时由 reader 保存的已校验地址显式返回，刷新不会静默重下。

## 1. 目标与准确边界

用户在 Chrome 打开在线文字版 PDF 后，点击扩展即可在**当前标签页**进入双语阅读；无需先下载再手动导入。译文可以出现在 PDF 页面的对应段落位置，而不只是右侧文字列表。

**技术路线：用户主动触发的阅读器接管 + 本地 PDF.js 渲染 + DOM 译文覆盖层。**

这里的“内嵌式”指译文嵌入扩展渲染的 PDF 页面，不是向 Chrome 原生 PDF 阅读器内部注入脚本。切换后地址栏将变为扩展页面地址，不承诺保留原 PDF URL、浏览器原生工具栏或原生阅读器的全部行为。不绕过 Chrome 的扩展隔离边界，也不自动接管所有 PDF。

### 本期交付边界

| 能力 | v2 方案 |
| --- | --- |
| 已打开的在线 PDF | 主文档为可重新获取的 HTTPS 直接 PDF 链接时，一键接管 |
| 当前标签页 | 用户确认后切换到扩展阅读器；提供“返回来源文件” |
| 本地 PDF | 继续支持选择和拖放；本地打开后同样支持页内译文 |
| 阅读模式 | 原文、页内译文、左右 PDF 对照；保留 v1 段落列表兜底 |
| 文件获取 | 扩展页在用户授权的来源主机上重新获取，不建设文件中转服务 |
| 翻译 | 复用现有后台，小批次、当前页按需、默认不自动翻页翻译 |
| 版式 | 保留 PDF 底图，按段落框覆盖译文；不承诺无损原版排版 |
| 不包含 | OCR、导出 PDF、全文自动翻译、永久接管、登录态自动处理、网页 iframe 内 PDF 自动发现、任意 blob URL 读取 |

重要区别：**浏览器已经能显示 PDF，不代表扩展可以再次取得其文件字节。** 临时签名、登录 Cookie、POST 响应、重定向、内存 blob 等均可能阻止重新获取，必须提供原文件阅读和手动导入回退。

## 2. 沉浸式翻译的公开参考与推断界限

官方说明公开了以下用户可见行为：

1. 在线 PDF 在浏览器打开后，可以点击扩展翻译该文件；本地 PDF 可通过专用入口导入。[PDF 文件翻译](https://immersivetranslate.cn/docs/features/pdf/)
2. 免费 PDF 模式采用纯文本识别，数学公式与表格处理受限。[免费 PDF 帮助](https://immersivetranslate.com/zh-Hans/docs/pdf-helper/)
3. 带图模式保留 Canvas 底图，用白色文本框遮盖原文后显示译文；译文框按原段落位置布局，支持调整位置、大小和重叠限制。[译文框与样式说明](https://immersivetranslate.com/zh-Hans/docs/pdf-helper/)

以上可作为交互与渲染思路的参考，但不能证明其直接修改 Chrome 原生 PDF 阅读器，也不能确认其完整内部架构。本项目独立实现，不复制闭源代码、私有接口或宣传“与其内部实现相同”。BabelDOC 的文档重排/生成能力不属于本期页内覆盖方案。

## 3. 用户流程

### 3.1 在线 PDF 接管

1. 用户在 Chrome 打开在线 PDF，点击扩展图标。
2. 弹窗展示版本与“在当前标签页打开 PDF 双语阅读”按钮，说明“将重新读取当前地址；不会立即调用翻译 API”。
3. 有 `.pdf` 路径时显示 PDF 候选提示，但不以扩展名作为文件类型证明。没有 `.pdf` 后缀的 HTTPS 文档也可由用户主动尝试此入口，最终检查响应与文件头。
4. 明确显示来源主机。仅当尚未获得所需来源主机权限时，在用户点击操作中请求该主机权限；用户拒绝则不导航、不获取文件。
5. 后台重新核对源标签页仍为用户刚选择的地址，建立有时效的来源记录，再把该标签页导航到扩展阅读器。
6. 阅读器认领该记录，显示“正在从来源网站读取 PDF”，有取消与返回入口。下载、校验、解析完成后展示页面，仍不自动调用模型。
7. 用户点击“翻译当前页”，切换到默认页内译文模式，逐段展示结果。翻页自动翻译仍需单独开启。

下载失败、不是 PDF 或权限失效时，不自动回跳造成循环；留在错误状态，提供“重试读取”“返回来源文件”“选择本地 PDF”。保留原始地址，仅向用户显示安全简化后的来源，不在错误提示暴露签名参数。

### 3.2 本地文件

本地选择/拖放沿用 v1，直接进入相同阅读模式。

对于已经在 Chrome 打开的 `file://` PDF，本期不新增全盘文件读取权限，也不要求开启“允许访问文件网址”；提示用户从本地导入。后续如需直接打开当前本地地址，再独立设计 `file://` 权限和用户开关，不把在线接管等同于所有本地文件也可接管。

### 3.3 界面草图

```text
PDF 双语阅读 v2                 paper.pdf · 来源 example.org
[返回来源文件] [打开本地文件] [设置 API]

第 [3] / 24 页  [上一页] [下一页]  缩放 [100%]
模式 [原文 | 页内译文 | 左右对照 | 段落列表]
[翻译当前页] [暂停] [停止] [重试失败项] [增加额度]
□ 翻页后自动翻译

┌──────────────────────────────────────────────┐
│ 图像、图表与页面背景：PDF Canvas                │
│ ┌──────────────────────────────────────────┐ │
│ │ 中文译文：位于对应原文段落位置               │ │
│ │ [查看原文] [展开全文] [调整位置]             │ │
│ └──────────────────────────────────────────┘ │
│ 未完成/失败段落：保留可读原文及小型状态标记      │
└──────────────────────────────────────────────┘
```

模式含义：

- **原文**：显示原始 Canvas，隐藏所有译文和遮罩。仅改变呈现，不改变队列状态；控制翻译使用暂停/停止。
- **页内译文**：在原始页面上用中文覆盖已成功翻译的段落；未成功的仍显示英文。它是混合语言阅读视图，不冒称“整页已翻完”。
- **左右对照**：左侧原始 PDF，右侧同页 Canvas 副本及译文覆盖层；不是旧版纯文字列表。窄屏改为上下排列。
- **段落列表**：保留现有英文/中文卡片，用于提取预览、复杂版面及覆盖效果不佳时兜底。

切换模式、缩放和布局调整都不触发 API；必须复用同一份段落与翻译状态，不因“左右对照”创建第二份翻译任务。

## 4. 来源获取：权限、认证与导航

### 4.1 分离三种授权

- **文件来源权限**：读取 PDF 所在网站，按具体 HTTPS 主机申请。
- **模型 API 权限**：现有设置页保存 Endpoint 并授权的 API 主机。
- **内容发送意图**：用户点击翻译，或明确开启自动翻页翻译。

三者不能互相代替。获取来源权限不允许自动上传全文；API Key 绝不能附到文件下载请求。可选 HTTPS 范围沿用 Manifest，新增来源主机用途的说明，不一次性申请全部网站权限。

不能假设 activeTab 一定能给原生 PDF 页面提供可用的跨域读取能力。优先在有可读来源 URL 的弹窗中展示并申请具体主机授权；若 Chrome 对某类原生阅读器不暴露 URL，就提供“粘贴当前 PDF 地址”兜底，不能为了识别文件而向受限阅读器强行注入或静默申请全面 tabs 权限。

权限申请必须位于真实用户手势中：弹窗先准备来源信息，按钮可用后，点击处理器立即请求已确定的 origin 权限，不在长串异步后台查询后才调用申请。申请结束后后台仍要核对源标签页状态。

### 4.2 本期网络策略

- 只接受无用户名密码的 HTTPS URL；允许查询参数以支持签名链接。URL fragment 不进入 HTTP 请求。
- 默认 `credentials: 'omit'`，不读取/转发 Cookie、Authorization 或网站页面凭据，不复用模型 API Key。不提供“遇到 401 自动带 Cookie 重试”。
- `redirect: 'error'`：本期不静默跟随重定向，避免越过已授权来源。遇到重定向提示用户在浏览器打开最终直接地址，或保存后导入。自动多跳授权留待后续。
- 只允许 GET，检查 HTTP 状态、响应类型及 `%PDF-` 文件头；不能仅凭扩展名或 Content-Type 接受。可允许 `application/octet-stream` 或缺少类型但头部确为 PDF 的响应；拒绝 HTML 登录页和截断/非完整响应。
- 使用 ReadableStream 分块计数；Content-Length 仅作提前判断，不可信赖它限制实际字节。实际接收超过 50 MiB 立即 abort；单来源同时最多一个下载，设置整体 60 秒与持续无数据 15 秒超时，支持用户取消。
- 本期不做 HEAD 预检、Range 分段下载和静默多次重试。下载额度与模型请求额度分开，获取文件不扣模型额度，但仍产生网络流量。
- 本期不主动接受回环/私有地址字面量作为来源，也不提供通用 URL 代理；主机名背后的地址解析不作强安全保证。仅处理用户主动选中的来源，不从文档、网页消息或重定向自动派生请求。

登录态、POST 生成、blob、data、HTTP、跨源重定向及过期链接均明确降级。读取失败不能宣称原文件损坏。重新获取到的文档可能与原生阅读器之前显示的版本不同；以实际获取后的字节和新文档身份为准，不根据 URL 直接复用旧译文。

### 4.3 阅读位置与返回

仅尝试解析公开 URL fragment 中明确的 `page=N`（1–500），校验总页数后定位；不保证读到原生阅读器当前滚动位置和缩放。不存在有效页码时从第一页开始，明确说明。

同标签页导航使用扩展正常页面导航能力，不尝试用 history/host hacks 让地址栏伪装为源站。返回按钮只恢复后台记录的来源地址及安全保留的 fragment，不接受文档/模型返回的新跳转地址。返回原生阅读器前停止翻译并取消下载；签名地址过期时原站也可能无法重新打开。

浏览器“后退”可按正常导航历史使用，不依赖其必然保留 PDF 原生阅读状态。不拦截用户关闭、返回或自行导航，也不在离开后自动拉回扩展阅读器。

## 5. 来源交接协议与生命周期

### 5.1 为什么不用 URL 查询参数

当前 PDF 后台只接受精确的扩展 `pdf.html`，带 query/hash 的阅读页也会被拒绝。继续保持这个边界：**不把源 PDF URL 或交接 token 拼到阅读器地址**，避免泄露签名参数并破坏既有来源校验。

来源交接与 `PDF_START/TRANSLATE/...` 翻译任务是两套独立协议。

| 消息 | 来源 | 职责 |
| --- | --- | --- |
| `PDF_SOURCE_PREPARE` | 精确扩展弹窗 | 使用目标 tab 与来源快照建立待导航记录；后台核对当前地址和用户触发上下文，不直接下载 |
| `PDF_SOURCE_CLAIM` | 精确主 frame 阅读页 | 按 sender 的 tab/document 认领来源，取得来源描述及读取凭证 |
| `PDF_SOURCE_STATUS` | 已认领阅读页 | 查询交接记录是否仍有效；仅返回小型状态 |
| `PDF_SOURCE_RELEASE` | 已认领阅读页 | 释放来源能力并标记取消；真正的 reader fetch 同时由阅读页 AbortController 取消 |
| `PDF_SOURCE_RETURN` | 已认领阅读页 | 后台校验拥有者后导航回保存的来源；不接受调用方指定跳转 URL |

具体字段在实施时固定为短标识、tab ID、预期源 URL/版本和随机读取凭证；不能把调用方传来的任意 URL 直接变成可读取记录。粘贴地址兜底必须是独立的显式输入/授权流程，也不能通过普通网页或 content script 调用。

### 5.2 交接状态

`prepared → reader-loading → claimed → fetching → ready / failed / cancelled → released`

- 后台在导航前再次 `tabs.get` 核对源地址，确认记录未被更新；每 tab 一个 pending 导航意图，后一次显式操作使前一次失效。检查与实际导航并非原子，需配合 tabs 更新事件失效记录，不能宣称消除所有用户并发导航窗口。
- 准备记录在后台内存中保存，建议 2 分钟未认领即失效；仅保存小型 URL/拥有者/时间信息，不保存 PDF 字节，不写 storage.local/sync。
- 首次合法主文档认领后绑定实际 reader tab/documentId；之后重复同拥有者查询幂等，其他 tab、子 frame、旧 documentId 或旧凭证都拒绝。认领过渡需考虑原始文档到 reader 的预期导航，不能被泛化的“URL 一变化即清理”误删。
- 认领后保留当前文档的来源描述直至关闭/释放，以支持返回；内存记录数量设全局上限（建议 20），过量新操作明确拒绝，不淘汰正在阅读的来源。
- 后台重启会丢失内存交接记录；未认领时提示“来源交接已失效，请从源 PDF 再试或导入本地文件”，不猜测来源。已认领且正在阅读的 reader 可继续使用其内存中的文件和来源地址，不自动再次获取；返回可由 reader 使用此前已验证的 HTTPS 来源显式导航。
- 阅读页刷新后丢失文件，不自动重下载；提供重新授权/显式重试路径。本期不建立跨会话文件库。

下载在阅读页中执行，不由 Service Worker 承载长时间文件下载，不把 ArrayBuffer/Blob 经 `runtime.sendMessage` 大体积传递。GET 的 URL 由认领记录决定，页面只选择重试/取消，不能由 PDF 正文或模型输出更改目标。

安全边界是扩展受信任代码和消息来源校验，不把 token 当成对扩展内部恶意代码的隔离。所有错误日志必须脱敏源 URL 的查询参数；来源全 URL 不发送给模型、不植入 DOM 属性或遥测。

## 6. 页内译文渲染设计

### 6.1 页面图层

```text
page viewport（position: relative，CSS 页面尺寸）
 ├─ 原始 Canvas：PDF.js 输出，永不改写 PDF 文件
 ├─ 译文遮罩层：仅遮盖已成功翻译且可安全定位的文字行区域
 ├─ 译文层：按块定位的纯文本 DOM，支持选中、展开
 └─ 控制/高亮层：原文切换、失败标记、调整手柄
```

Canvas backing pixels 与 CSS 像素分离；devicePixelRatio 只影响清晰度，不能重复乘进 DOM 定位。v1 已输出应用页面旋转、CropBox 偏移与 UserUnit 后的单位缩放左上角 rects，v2 必须保持这一约定并补实际文件坐标测试。

所有段落坐标与手动调整保存为单位页面坐标，显示时仅乘当前缩放；缩放/窗口大小变化不能修改原始坐标或重新调用模型。旋转方向改变时统一通过视口变换重算，首期若不提供额外旋转按钮，也必须验证文档自带的标准旋转。

### 6.2 遮盖规则与保守降级

- 原文、待翻译、失败或部分切片成功的段落，默认保留底图英文；成功切片可在展开面板查看，但不以不完整中文覆盖整段。
- 仅当整块切片全部成功、坐标有效且具有足够布局可信度时，生成遮罩和译文框。
- 优先逐文字行 rect 遮盖，而不是给整个段落外接矩形涂白，以减少图像/公式/其他栏误遮。白色遮罩仍会改变彩底或贴近图表的效果，不能宣传“完美还原原图”。
- 现有 rects 近似字形框，默认遮罩少量内收、文字框留边；不能因追求盖干净而随意扩大到相邻栏。
- 对文字方向不支持、跨栏、显著重叠、异常大框或提取警告严重的块，不自动覆盖，显示页边标记并引导到段落列表。v1 的启发式警告不能当成可靠的图像区域检测器。
- 彩色背景、文字压图和公式混排无法可靠判断时，提供“关闭遮罩，仅显示译文浮框/查看列表”；允许用户随时按住/点击查看该段原文，且不触发翻译。
- 不直接把原文“擦除”到 Canvas，也不修改原 PDF，切回原文必须无损可见。

### 6.3 字号与溢出

提取模块补充块级 `fontSize`、行高估计和布局风险标记。中文字形使用随系统可用的中文字体，默认字号接近原文字号，并允许用户调整译文比例（建议 80%–140%）。

**首期不以自动无限缩小字号解决溢出，也不让译文默认覆盖下一段。**

- 默认框宽与原段落栏宽接近，高度受原段落区域和邻近块安全间距约束。
- DOM 实际布局后检查 scrollHeight/scrollWidth；超出时显示“展开全文”，在页外抽屉展示完整译文及原文，不静默截断。
- 失败提示、小型按钮和展开面板本身也必须可访问，不通过把所有内容压进狭小原框来处理。
- 字号、行距和显示框变化只是呈现设置，不改变源文本、切片 ID 或缓存键。

### 6.4 手动调整

本期提供：移动译文框、调整宽高、单块隐藏译文、恢复本页默认布局。框不能拖出页面边界，提供键盘等效操作；拖动手柄与文字选择区域分开。

调整只改变译文框，不移动底图；原文遮罩仍绑定原始文字坐标，不能跟随译文框拖走后把另一处内容盖住。关闭译文框时同时移除其遮罩，恢复该段英文。

所有调整按 documentId/page/block/extractionVersion 存在 reader 内存；缩放和模式切换保留，关闭/刷新不保留。源文本编辑、段落合并拆分、持久化布局和“删除原文段落”留待后续，避免引入文本修订与计费身份的新复杂度。

## 7. 状态、调度与数据模型

复用 v1 的文档、页、block、chunk；不为每个显示模式复制文本或创建新任务。

```text
SourceSession:
  sourceId, sourceKind(local|https), sourceURL(私有内存), sourceTabId,
  readerDocumentId, sourceEpoch, fetchState, displayHost, initialPage

BlockLayout:
  blockId, extractionVersion, sourceRects[], defaultBox,
  fontSize, layoutRisk[], overrideBox?, hidden, overflow

ReaderView:
  mode(original|inline|sideBySide|list), zoom, viewEpoch, controlEpoch
```

- fetchEpoch 区分下载/换源；现有 generation/controlEpoch 区分文档和翻译意图；viewEpoch 区分翻页/缩放/模式绘制。任何异步完成必须验证对应版本。
- 显示变化不改变翻译身份。只有源文字/模型/提示词/凭据相关变化才使翻译结果失效。
- 翻页不预取；旧页已派发响应可保留在旧页记录，但不能在新页生成遮罩。
- 停止必须使尚未完成的下载后自动动作、PDF_START、延迟自动翻译、遮罩布局测量全部失效；停止翻译与取消文件获取在 UI 上分别命名，不能混淆“取消翻译”与“关闭文件”。
- 下载/解析成功绝不隐式调用模型。开启自动翻页也不表示允许对所有尚未浏览页面发请求。
- 切换显示模式不暂停或重开已有翻译，停止/暂停/增加额度继续沿用现有明确语义。切换到原文不会清除结果。
- 保持全扩展两 API 并发、每文档累计额度、手动重试和缓存规则；来源重试不使用模型额度。未知结果不得自动重发。
- 新文档源即使 URL 相同也生成新 documentId，不根据源 URL 把用户文件、凭据或译文跨标签页合并。

## 8. 性能与资源

继续采用 50 MiB、500 页、单页 50,000 文字项/200,000 字符和约 20 MiB 文字预算；下载大小限制不能替代解析阶段资源限制。

左右 PDF 对照最多共享一个 PDF.js 文档与同页解析结果。首选一次渲染后将已完成 Canvas 复制到第二个画布，不做第二次全文解析；两块画布及临时副本**合计**受约 12 百万 backing pixels 预算约束，高 DPI 时降低输出倍率。

只保留当前页画布、当前页 DOM 覆盖层与必要文字状态。翻页取消旧渲染，关闭/换文件释放流、AbortController、原始字节引用、Worker、画布、事件和对象 URL。分批生成译文框，不在每次片段响应时重建整个页面所有节点；溢出测量合并在 requestAnimationFrame 中，禁止 ResizeObserver 写入循环。

不做后台常驻下载保活，不以 setInterval 防止 Service Worker 休眠。来源记录丢失时显式降级，不重建未知请求。

## 9. 安全与隐私要求

- 不新增远程执行代码、脚本注入原生阅读器、外部消息入口或任意网站可调用的下载代理。
- 新来源协议严格校验精确扩展页、sender.id、主 frame、tab/document、凭证和来源 epoch，不能只用通用 trusted 前缀。
- 源网站请求与 API 请求有独立构造器，测试确认不会串用 Authorization、Cookie 或请求正文。
- 密码继续仅在阅读页临时使用；复制受限文档不提供绕过；文档脚本、嵌入动作、附件和任意外链仍不执行。
- 文件名、原文、译文均用 textContent；不执行模型 HTML/Markdown，覆盖层不通过用户文本生成 CSS。
- 遮罩不是删敏工具：原文仍在 Canvas、内存和原文件中。不能用于导出“已脱敏 PDF”，也不承诺图片或脚本恶意文档绝对安全。
- 下载 URL 可能包含访问令牌；不写日志、持久设置或遥测，不发给模型。复制来源链接必须由用户明确操作，并提示可能包含临时访问参数。
- 权限撤销后停止新的下载，已有本地文档仍可阅读；API 主机权限撤销继续使用现有错误提示，不因获取文件授权而自动恢复。

## 10. 拟议模块与实施顺序

以下为职责规划，路径均需在实施时新增或修改：

| 模块 | 职责 |
| --- | --- |
| `extension/popup.html` / `popup.js` | 版本可见、当前 PDF 入口、来源主机提示与手势内授权 |
| `extension/pdf-source.js` | 受控来源 URL/响应校验、流式限额、取消、下载状态 |
| `extension/pdf-source-session.js` | 后台来源记录、导航意图与精确消息授权；与翻译账本分离 |
| `extension/pdf-overlay.js` | 单位坐标布局、遮罩、译文框、溢出与手动调整 |
| `extension/pdf.js` / `pdf.html` / `pdf.css` | 来源加载、四种模式、返回入口、状态整合 |
| `extension/pdf-extract.js` / `pdf-state.js` | 补充布局元数据，不破坏现有文字与 ID 契约 |
| `extension/background.js` | 接入来源协议，保留现有 PDF 翻译来源与额度校验 |
| `tests/pdf-source*.test.mjs` | URL/响应/大小/来源/导航状态与认证隔离 |
| `tests/pdf-overlay*.test.mjs` | 坐标、布局、溢出与手动调整纯逻辑 |
| `scripts/pdf-smoke.mjs` | 真实扩展远程获取与页内模式验证，保留既有回归 |

分三阶段：

1. **来源接管闭环**：公开 HTTPS 直链 → 具体主机授权 → 同标签页阅读器 → 受限下载 → 本地解析；失败、取消、返回和无模型调用均可验收。
2. **页内呈现闭环**：成功整块遮罩与译文定位、模式切换、溢出抽屉、原文查看、保守降级和布局调整；本地导入同样可用。
3. **稳定性与交付**：实际坐标样本、权限/导航/生命周期竞态、画布资源预算、现有网页/PDF 回归、版本与使用说明。

## 11. 验收标准

### 入口与获取

- [ ] 在真实 Chrome 顶层打开公开 HTTPS 文字 PDF，用户操作后同标签页进入扩展阅读器，不需本地下载导入。
- [ ] PDF 候选识别不依赖唯一的 `.pdf` 后缀；HTML 页面不被误当文档，未知来源显示可理解的尝试/回退入口。
- [ ] 来源权限拒绝时不导航、不下载；来源/模型主机权限明确分开，真实权限提示需手工验证并记录 Chrome 版本。
- [ ] 预览不产生模型请求；来源 GET 无模型密钥/网页 Cookie；不跟随重定向，不访问文档给出的任意新 URL。
- [ ] 无 Content-Length、错误长度、流式超限、长时间无数据、401/403、HTML 登录页、过期链接与异常响应可控失败。
- [ ] 用户关闭/导航/重试/换文件使旧下载和来源交接失效；原生阅读器不可读 URL、file/blob/POST/登录态来源能明确回退。
- [ ] 带敏感查询参数的地址不会泄漏到日志、阅读器 URL、模型请求或持久设置。

### 页内译文

- [ ] 单栏、常规双栏、非零 CropBox、UserUnit、文档自带旋转及不同 DPR 样本中，原始 rect 与覆盖位置可人工核对。
- [ ] 全段成功才覆盖；失败/部分成功段不丢失可读英文，旧页/旧文档结果不会生成新页遮罩。
- [ ] 四种模式共享结果；切换、缩放、拖动/调整大小不调用 API，切回原文无损显示底图。
- [ ] 中文溢出有可见标记与完整展开，默认不覆盖邻段、不无限缩小、不静默截断。
- [ ] 移动/隐藏译文框不会留下错误位置的遮罩；高风险版面提示回退到列表而非声称原版还原。
- [ ] 译文可选择复制，控件能键盘操作；模型返回 HTML/脚本只显示文本。

### 生命周期与回归

- [ ] 同标签页接管不自动获取原生阅读器内部状态，页码无法恢复时明确从第一页开始；返回来源停止当前请求。
- [ ] 在准备记录、权限申请、导航、认领、下载、解析、PDF_START、翻页和覆盖层测量各等待点插入取消/停止，均不会重开未知请求或自动付费。
- [ ] Worker 重启、刷新、来源记录过期和权限撤销有明确降级，来源记录不能被其他标签页冒领。
- [ ] 两 API 并发、累计额度、缓存、未知结果手动重试不回退；左右对照不翻倍计算或重复请求。
- [ ] 真实 Chrome 验证本地 Worker/CSP、至少一个公开 HTTPS PDF 与失败回退；另以可控服务器验证响应异常。权限检查模拟与真实浏览器授权的结论分开记录。
- [ ] 原有网页翻译、本地 PDF 导入和 41 项测试保留通过，新测试按实际覆盖报告；复杂文档、内存压力和未测浏览器版本不作未经验证的承诺。

## 12. 本方案需要确认的默认决策

1. “内嵌式”采用**主动接管到扩展阅读器**，地址栏会改变，不修改原生阅读器内部。
2. 在线接管先支持**可公开重新获取的 HTTPS 直接 PDF**；登录态、重定向、blob 和本地直接地址先回退导入。
3. **页内译文为主要新模式**；保留原文、双 PDF 对照和段落列表，方便核对与降级。
4. 只做阅读覆盖，不生成新的 PDF，不做 OCR，也不默认自动翻完整本文档。
