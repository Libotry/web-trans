# 双语阅读 · 自带 API

Chrome Manifest V3 扩展，版本 1.1.0。支持网页逐段双语翻译与本地文字版 PDF 对照阅读；使用用户自己的、兼容 Chat Completions 协议的大模型 API。

项目仓库：[Libotry/web-trans](https://github.com/Libotry/web-trans)。可使用 Git 克隆仓库，或在 GitHub 点击 Code → Download ZIP 下载，再按照下面步骤加载 extension 文件夹。

初始设计见 [设计文档](docs/design-v1.md)，已实现行为和限制以本文及 [验证记录](VERIFICATION.md) 为准。

## 安装

1. 在 Chrome 地址栏输入 `chrome://extensions/`。
2. 开启右上角“开发者模式”，点击“加载已解压的扩展程序”。
3. 选择本项目的 **extension 文件夹**，该文件夹内有 `manifest.json`。
4. 在工具栏拼图菜单中固定“双语阅读 · 自带 API”。

不需要安装 Node.js、Python 或任何 npm 包即可使用。不要删除或移动已加载的 extension 文件夹。修改源码后，在扩展管理页点击重新加载，再刷新目标网页。

## 配置和使用

点击扩展图标 → 设置，填写：

- **完整 HTTPS 请求地址**：服务商的聊天补全接口，例如 `https://你的服务域名/v1/chat/completions`。不是 API 官网首页，也不是只到 `/v1` 的基础地址；扩展不会自动拼接路径。
- **模型名称**：填写服务商提供的准确模型 ID。
- **API Key**：通过 `Authorization: Bearer ...` 发送，仅支持这种鉴权方式。

点击“保存并测试连接”，Chrome 可能提示授权该 API 域名。扩展只申请你填写的主机，不会一次性申请全部网页的永久访问权限。连接测试会发送一句内置短句并可能计费。

Key 默认仅保留在浏览器会话，重启 Chrome 后需要重新填写。勾选“记住 Key”才写入本机持久存储。设置页不会回显已保存密钥；密钥框留空表示保留，点击“删除已保存的 Key”才能清除。

打开普通英文网页，点击“翻译此页”。默认正文优先，可改为页面文本。扩展先处理当前视口和下一屏，继续滚动即可翻译后续段落；没有滚动到的远处内容不会提前产生请求。动态新增的段落也会处理。

- **暂停/继续**：控制后续请求，已经发出的请求可能完成。
- **隐藏/显示译文**：隐藏时暂停新增请求；显示后恢复之前的暂停状态。
- **恢复原文**：移除译文，取消本页任务，并尽力中止请求。
- **重试失败段落**：由用户主动重试，可能产生额外费用。
- **增加额度**：达到单页上限后出现，点击后允许再使用一份设置中的请求额度。

修改模型或样式后，恢复原文再重新翻译。重复开始会替换当前页面任务；相同模型、凭据及相同批次文本可以命中缓存。

## 文字版 PDF 翻译

1. 在扩展管理页重新加载扩展，然后点击扩展弹窗的“PDF 双语阅读 · 打开本地文件”。
2. 点击“打开 PDF”或将单个本地 PDF 拖入阅读页。Chrome 内置阅读器中已打开的 PDF，请先保存到本地，再导入。
3. 左侧保留 PDF 原始页面，右侧显示提取的英文段落。确认顺序后点击“翻译当前页”，显示对应中文。
4. 翻页默认不自动翻译；需要时再次点击按钮，或主动开启“翻页后自动翻译”。不预取下一页。

文件在本地解析，仅发送待翻译文字；打开和预览文件不调用模型。沿用设置页 API 配置，无需额外文件访问权限。点击右侧原文可近似高亮对应 PDF 区域。

- 最大 50 MiB、500 页；文字内容有内存预算，达到上限会停止继续处理。密码仅在阅读页临时输入，复制受限文件不提供绕过功能。
- 单栏与常规双栏优先；复杂排版、表格、公式和字体编码可能提取不准，应先检查原文预览。扫描页需要 OCR，当前不支持。
- 暂停停止新增请求；停止尽力取消在途请求并保留已有译文；失败项仅手动重试。取消/超时仍可能计费。
- 同一个已导入文件各页共用请求额度（默认 100 次），停止、重新开始、清除译文都不归零；增加额度才追加配额。重新导入文件会创建新文档任务。
- 网页与所有 PDF 阅读页共享最多 2 个并发请求及有界会话缓存。清除本文件译文不清后台缓存；设置页“清除缓存”不移除已经展示的译文。
- 切换 API、模型或密钥后任务会暂停；重新开始会清除当前文件旧配置的译文，避免混用。字号等纯展示设置不影响翻译身份。
- **刷新/关闭阅读页、扩展重载或浏览器重启后需重新选择文件。** 原 PDF 字节、密码和完整阅读结果不持久保存；后台只保留会话级批次缓存和任务计数。每个阅读页最多保留最近 10 个文档的会话计数记录。
- 暂不支持直接抓取 PDF 链接、OCR、整本自动翻译、导出译文 PDF或接管 Chrome 内置阅读器。

设计与边界见 [PDF 设计方案](docs/design-pdf-v1.md)。

## 接口兼容与排障

请求使用 `POST`、非流式 `messages` 格式，读取 `choices[0].message.content`。扩展要求模型在文本中返回带段落 ID 的 JSON；不要求服务本身提供原生结构化输出。支持时可勾选 JSON 模式，会增加 `response_format: {type: "json_object"}`。

没有内置特定厂商 SDK，也没有固定模型清单。其他原生协议、流式接口、查询参数鉴权、HTTP 本地模型、无需 Key 的服务暂不支持。尚未使用真实服务商 Key 验证具体厂商，不能将协议兼容理解为所有服务都已测试。

常见问题：

- 401/403：检查 Key 和模型权限；修正后重新开始任务。
- 402：检查余额；修正后重新开始任务。
- 404 或返回不是 JSON：检查完整 Endpoint。
- 429：限流或配额不足。第一版保守地采用手动重试，不自动重复请求。
- 无效 JSON/缺少译文：可尝试支持 JSON 模式的模型，或手动重试。
- 超时：默认 25 秒，可设 5–25 秒。慢速推理模型可能不适用。
- 刚安装或重新加载后无反应：刷新目标网页，再点击翻译。
- 浏览器提示不能访问：`chrome://`、扩展商店、内置 PDF 等受限页面不能注入；PDF 请通过扩展的 PDF 阅读入口导入本地文件。

## 隐私、费用和限制

固定权限只有 activeTab、scripting、storage。点击翻译后才扫描页面，不自动翻译其他网站。配置域名权限通过可选权限申请。

Key 仅在扩展后台请求 API 时使用，不传给 Content Script、不进入页面 DOM 和日志、不使用 Chrome 同步。持久化 Key 不等于加密保险箱，本机账户仍可能读取。发送到模型的只有待翻译段落及提示词，不发送网页 Cookie、完整 DOM 或浏览历史。服务商的数据留存政策由其决定。中文插入网页后，网页脚本可能读取它。

默认全扩展最多两个并发请求，每页默认 100 次，用户可设置 1–1000 次。缓存默认只在当前浏览器会话有效，容量有界，可一键清除。缓存以请求批次为单位，段落分组变化可能导致重新请求。用量只显示服务返回的 token，不估算人民币费用，也不构成账单。取消和超时不能保证服务端停止计费。

后台关闭后，正在等待的页面请求会成为失败或结果未知，由用户手动重试；已完成会话缓存和已消耗额度保留。刷新网页或 Chrome 重启后，需要重新点击开始。动态路由切换会重新建立本页任务，页内普通锚点不触发重翻。

优先支持普通文章、文档、标题、列表、普通表格和 div 文本布局。保留英文富文本，译文使用纯文本，不承诺复制中文链接和强调格式。输入框、编辑器、代码块、隐藏内容、导航操作区、中文段落默认跳过。PDF 不走网页注入，而通过独立阅读页导入。图片、视频、iframe、Shadow DOM 内正文、Canvas 和复杂布局不在网页模式适配范围。插入中文会让页面增高，可能产生阅读位置变化。

## 开发与验证

可直接加载 extension 目录，采用原生 ES modules + DOM。PDF.js 6.4.299 的兼容版模块、Worker、字符映射、字体和许可证已随扩展打包，不从 CDN 加载；禁用 Wasm，保持现有严格 CSP。部分依赖 Wasm 解码的 PDF 图像可能无法显示，文字提取与原始图像渲染不保证覆盖所有文档。

只有开发者更新依赖时才需要执行 `npm ci --ignore-scripts --omit=optional` 和 `npm run vendor:pdf`。固定版本与完整性由 lockfile 记录，已打包资源的来源和 SHA-256 清单见 `extension/vendor/pdfjs/PROVENANCE.json`；`npm run check` 会逐项校验。最终用户不需要安装 npm 包。

使用 Node.js 24，在项目根目录运行：

```powershell
npm run check
npm test
npm run smoke
npm run smoke:pdf
```

`npm test` 包含核心协议、后台调度和无头 Chrome 页面集成测试。默认寻找 Windows 标准路径 Chrome，可通过 `CHROME_PATH` 指定其他安装位置。`npm run smoke` 使用 Chrome 的扩展调试接口加载实际扩展，验证 activeTab、后台、设置页、注入和消息链路；需要支持该调试接口的较新 Chrome。`npm run smoke:pdf` 使用自生成的两页 PDF，实际加载本地 PDF.js Worker 并验证导入、按页翻译、翻页不预取、缩放复用、缓存及取消计数。所有浏览器测试使用独立临时配置与模拟模型，不使用个人浏览器配置或真实 Key，不产生模型费用。

测试截图 `demo.png` 展示的是模拟接口的页面效果，部分文本仅使用测试占位译文；`settings-preview.png` 来自实际加载的扩展设置页。
